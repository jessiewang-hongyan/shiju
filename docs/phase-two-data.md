# 二阶段数据与迁移设计

更新：2026-11-04。状态：作品模型与迁移器已在 2A 落地，2B 已接入按作品存储、视图存储、多原文编辑及冲突界面，2C 已接入独立纸张覆盖与布局缓存；2D 已启用导出范围和顺序，尚未部署。实现、偏差和容量证据见 [2A 记录](phase-two-2a.md)。主方案见[开发方案](phase-two-plan.md)。

## 当前约束

`storage.js` 当前保存 `{source, tokens, title, signature}`；`tokens` 以 `{c,id}` 表示文字，`id:null` 表示插入字符。`source-parts.js` 把正文、标题、作者排到同一个编号空间；标题／作者起点由正文和标题长度计算。`editor.js`、`editor-paper.js`、`image.js` 都依赖这套单篇编号。`collection.js` 以单个 `source.title` 生成来源摘要，字体加载也需核对单原文读取点。

因此不得简单给每个 Tab 重新从 0 编号、直接拼接原文，或用 Tab 下标作为永久出处。

## 拟议作品格式

以下为概念示例，不是可直接写入现版本的 JSON：

```json
{
  "schemaVersion": 2,
  "documentId": "doc-uuid",
  "revision": 1,
  "title": "花间",
  "signature": "",
  "sources": [
    {
      "instanceId": "source-uuid",
      "workKey": "catalog:provider:collection:record-id",
      "snapshot": {
        "title": "桃花庵歌",
        "author": "唐寅",
        "text": "所选原始正文",
        "collection": "明"
      },
      "provenance": {
        "recordId": "原记录ID",
        "dataCommit": "固定数据版本",
        "sourceCommit": "上游版本（若有）"
      },
      "selection": {
        "startParagraph": 2,
        "endParagraph": 3,
        "bodyStartCodePoint": 33
      },
      "paperOverride": null,
      "paperSeed": "persistent-seed"
    }
  ],
  "tokens": [
    {
      "tokenId": "token-uuid",
      "kind": "cut",
      "raw": "花",
      "origin": { "sourceId": "source-uuid", "part": "text", "offset": 5 }
    },
    { "tokenId": "insert-uuid", "kind": "insert", "raw": "，", "origin": null }
  ],
  "imageSettings": {
    "sourceDefaults": {},
    "poemPaper": {},
    "sourceSelection": { "mode": "used", "ids": [] },
    "sourceOrder": { "mode": "tabs", "ids": [] },
    "collageSeed": "persistent-seed"
  }
}
```

- `sources` 数组顺序是 Tab 顺序；`instanceId` 不随排序、刷新或撤销变化。`workKey` 用于同一来源记录的重复检测，`instanceId` 用于作品内引用，两者不混用。
- 稳定来源记录 ID 存在时，`workKey` 不因数据提交更新而变化；提交号独立保存作溯源。不同来源版本有不同身份，不能按作者与标题拼接猜测唯一性。缺少稳定 ID 的路径必须明确建立规则。
- 自定义原文的重复检测使用标题、作者、原文三元组的哈希，只统一换行符；不要先做繁简转换或删除空缺符号。
- `origin.offset` 是该原文快照对应区域中的 Unicode 码点索引，使用 `Array.from` 口径，非 UTF-16 下标、非转换后文字、非视觉行列。选段来源位置通过 `selection` 映射；正文内部不能再用会变化的标题偏移编号。
- 快照包含实际使用的选段以及已有作者、标题、来源、缺文和通知字段；恢复不重新联网。再次选段时可按来源取全文；失败保持旧快照。自定义文本没有外部全文时只对当前快照选段，或重新输入。
- 剪下字的 `raw` 与快照该位置一致。繁简转换仅改变显示，保持身份与字符数的一对一约束，延续当前异常扩展回退规则。
- 所有原文标题、作者、正文均可作为出处。插入字元没有出处；缺文标记作为普通来源位置保留，不能当成插入字符。
- 2C 的纸张覆盖按整组保存：`null` 代表全部跟随默认；独立设置保存 `{key, background, strength}`，分别为合法纸张枚举、六位十六进制颜色、0–200 的整数深浅。界面明确选择“跟随默认”或独立设置，不提供逐字段继承。这替代早期拟议的部分字段覆盖，避免默认纸张变化与旧覆盖深浅混合。来源墨色沿用共享颜色及纸张派生逻辑。
- 布局坐标不写入作品。`source-layout.js` 共用交互与测量排版，`editor-paper-v2.js` 仅缓存最多 10 篇的数值几何，字体、字号、宽度、繁简显示或快照变化后失效。`paperSeed` 与来源区域／码点位置生成稳定纸片种子。详见 [2C 记录](phase-two-2c.md)。
- 活动 Tab、滚动位置、当前选中的集句字块、弹窗预览来源属于视图状态，单独保存，不改变作品 revision 或占撤销历史。恢复时若原文被移除，则选择邻近 Tab，空列表显示添加入口。

## 2D 实际导出设置

`sourceSelection` 的 `used` 模式动态选择贡献字块的原文，`manual` 模式使用保存的 ID 集合。`sourceOrder` 的 `tabs` 模式跟随来源数组，`manual` 模式保留当前选中原文的顺序，新选项追加。取消选择／移除来源会清理相应顺序引用，撤销恢复整份设置。

新增可选 `imageSettings.sourceGap`，整数 0–160，缺省 40。预览来源只保留在控制器中，不写入作品。导出前复制文档、显示文本与设置，再按冻结字符集加载字体；不将临时几何和预览截断文本保存为作品。见 [2D 实现及验收边界](phase-two-2d.md)。

## 不变量与命令边界

1. 原文 ID、字块 ID 在作品内唯一；每个裁剪字的来源存在，区域合法，位置在边界内。
2. 一个原文位置最多对应一个裁剪字；同一个汉字在其他位置、其他原文中可独立出现。
3. 已用位置集合由 tokens 推导，不另存一份空位表，避免两份状态不同步。
4. 每个状态修改经过统一命令与校验，之后再渲染、持久化；不能由 DOM 推断权威作品状态。
5. 删除原文、关联字块和导出引用是一次事务性命令；撤销恢复准确顺序和设置。身份与随机种子不得在撤销时重新生成。
6. 持久化失败要明确显示“未保存”，保留内存创作，不谎报成功；迁移和诗集保存读回验证成功后才显示完成。
7. 异步加载使用请求身份与取消信号校验，旧请求返回不得修改当前文档。导出读取冻结快照，导出中用户继续编辑不改变正在生成的内容。

正式搜索运行时还由 `scripts/build-release.mjs` 组装并替换部分模块和页面内容。修改原文弹窗或模块接口时必须同步检查这些构建转换，验收最终构建包，不能只运行 `dist/` 开发页。

避免一口气重写所有模块：先提供旧单原文适配器，逐步替换调用点；适配器只用于过渡，不在新作品中维护两套可写状态。编辑与导出共享布局规则，按各自可用宽度生成不同坐标。

布局缓存至少包含文档内原文 ID、快照修订、文字转换、字体就绪状态、字号、可用宽度、纸张参数和种子。字体异步就绪、ResizeObserver、设置变更都需失效；Tab 切换不能成为随机参数的一部分。计算绘制尺寸与实际使用的字体一致后才发布新几何结果。

## 存储迁移和回退

2A 已选择独立 IndexedDB 库 `shiju-v2`，不写旧 localStorage 键，不维护两套存储后端。2B 将数据库物理版本升级到 2：`workspace` 只保存轻量元数据与作品 ID，`documents` 按作品保存，`views` 独立保存每页活动 Tab 与滚动位置，`backups` 保存迁移与恢复前记录。升级在同一事务中完成并保留升级前备份。普通自动保存只更新当前作品及元数据，不再重写全部诗集；迁移、完整备份恢复仍为批量操作。首次打开和诗集列表仍读取所有作品，这是后续可优化的边界。

迁移顺序：

1. 只读读取旧 `shiju-draft` 和 `shiju-collection`，验证结构，保留原字符串和已有作品 ID。备份无法写入时停止迁移，不能先覆盖旧数据。
2. 每份旧作品创建一个来源实例。用旧 `sourceParts` 规则解码数值 ID：正文为原 ID；标题、作者分别减去当时的区域起点。`id:null` 转为插入字符；分隔符空洞和越界 ID 不能猜配到相邻字。
3. 给 token 分配稳定标识，验证快照、文字、标题、署名、空位、数量与顺序。旧版没保存到作品里的历史图片设置不能凭空恢复；使用现有有效设置作迁移初始值，并在记录中说明来源。
4. 写入独立新版数据及迁移标记，读回并校验。首次打开未完成时可重新执行，必须幂等，不重复产生诗集作品；迁移标记不能领先于数据成功写入。
5. 下一次优先读取合法新版数据。新版损坏或版本高于当前支持时，保留原数据并提供恢复路径，不静默回退到旧版后覆盖；坏诗集项保留可诊断原始数据，不吞掉后当作成功全部迁移。

旧页面继续写旧键不能覆盖新版作品。迁移后旧键若又变化，不自动覆盖或合并新版；在新版提示存在旧版编辑记录，提供明确的“作为独立作品导入”，并去重已导入记录。双新版标签页使用 revision／写入实例信息识别冲突（2A 已实现原子版本检查；2B 已接入界面通知与保留副本／重载），阻止无提示覆盖，提供保留副本或重载选项。

旧版回退只能读取旧版备份，不会显示新版多原文作品；新版数据必须保留，恢复新版后仍可打开。旧版不能被假定能解析多原文，也不能将“旧版本可访问”写成“可继续编辑所有新作品”。图片不是可恢复全部编辑状态的备份；需要提供可恢复的作品数据备份入口，至少用于迁移失败与恢复流程。

现有设置键也需审计：作品中的纸张和导出配置保存为快照，新版只在创建文档时读取用户默认；不能让旧标签页修改一个全局偏好就无提示改变新版作品。搜索偏好、夜览等非作品数据可独立保留。

## 历史与容量策略

先保持撤销最多 100 步的现有上界，但不可盲目把多篇全文重复序列化 100 份。来源快照不可变，历史使用结构共享或命令差量；历史还需受字节预算约束，由测量决定阈值。移除／撤销原文必须保留准确快照直到相关历史释放。

不得把压力阈值写死为无依据的篇数。发布前必须记录：正文／作品 JSON 大小、存储写入耗时、历史峰值、活动 DOM 数量、布局缓存、导出内存及图片尺寸；最终产品限制和失败提示写回主方案。
