# 独立搜索服务上线方案与成本评估

评估日期：2026-10-29。仅评估；没有创建云资源、购买套餐、修改 DNS 或部署。价格为本日核查的公开美元标价，税费、汇率、优惠及账号合同另计。

## 建议

第一阶段保留 GitHub Pages 编辑页，增加一台常驻 Node 搜索服务；原文与索引作为版本化只读数据随服务发布。继续复用现有搜索算法，不引入数据库、Redis、独立搜索引擎或 Kubernetes。只将搜索条件发给服务，草稿、裁剪、纸张合成和图片导出仍在浏览器执行。

希望减少运维，优先评估 Render 新加坡、1 CPU / 2 GB 常驻实例；基础计算费 $25/月，建议小规模预算 $25–35/月。愿意自行维护 Linux，DigitalOcean 新加坡 1 vCPU / 2 GiB 是低费用备选，基础 $12/月，建议预留 $15–20/月总预算。两者都是待压测的起始规格，不是已证实的容量承诺。大陆访问质量需另测，地理位置不能代替线路验证。

## 当前项目证据与资源需求

- 19 类外部文集，443,692 条；精选 8 篇在前端独立提供。
- 本日按文件逻辑字节累计：归一化两套索引 192.58 MB、宋原文分片 156.07 MB、现有文集 parts 86.88 MB、排序表 18.76 MB，合计约 454.29 MB。加代码、目录/版本清单和运行时依赖后仍需打包实测；不能把 0.45 GB 当作完整容器大小。上述 parts 可能包含历史文件，暂未清理。
- 构建目录同时保留合并 JSON、原始索引等，不能全部照搬到云端。运行镜像只带实际引用的文件；保留旧版回滚产物，预留至少 5 GB 发布空间。
- `prototype/search/verification.json` 中 25 个场景的本机 HTTP 时间约 24–166 ms，包含缓存因素；搜索响应 gzip 约 0.09–3.97 KB（含空结果）。这些不是云服务器、手机、冷启动或并发 p95。
- 现有 worker V8 老生代限制 384 MB，不是进程 RSS 上限；另有主线程、临时对象和缓存。现有结果不足以证明 512 MB 实例稳定。推荐以 2 GB 起步，后续根据持续 RSS/峰值和延迟决定是否缩配。
- 当前只有一个串行 worker，队列上限 16，过载返回 503。不能从单请求耗时直接换算可服务人数，也不能认为增加核数自动提高吞吐。

## 按使用量测算

没有真实访问统计，以下是情景计算，不是用户量预测。以每次搜索结果（包括翻页）平均 10 KB 出站、每次打开全文平均 10 KB、每 5 次搜索打开一次全文计算。10 KB 是用于留余量的假设，不是实测均值；特别长的作品及取消/重试请求会增加实际量。

公式：月 API 出站 ≈ 搜索请求数 × 10 KB + 全文请求数 × 10 KB。输入过程可能多次触发搜索，因此不是“一位访客等于一次请求”。

| 月搜索请求 | 月全文请求 | 估计 API 出站 | Render 计算费 + 出站估算 |
| --- | --- | --- | --- |
| 10,000 | 2,000 | 0.12 GB | $25/月 |
| 100,000 | 20,000 | 1.2 GB | $25/月 |
| 1,000,000 | 200,000 | 12 GB | $26.05/月 |

假设 Hobby 5 GB 额度全部可供本服务使用，不含协议开销、其他服务流量与税。最后一行只计算流量费，**不表示当前单 worker 可以满足百万请求的峰值并发**。费用更可能因需要更多计算实例而上涨，而非几 KB 摘要的流量上涨。图片在客户端生成，不产生服务器图片渲染费或 AI token 费。

建议小规模年度预算：Render $300–420；自行运维 VPS $180–240。均为工程预算，不是固定账单报价；域名、构建产物托管、备份、税费和人工维护分别核算。VPS 基础计算费本身为 $144/年。

## 上线前必须完成的项目改动

1. **公网连接**：前端目前固定相对 `/api/`，需要显式 API base URL；GitHub Pages 到独立 HTTPS 域名属于跨域。配置允许当前 Pages Origin 的 CORS，保持无 Cookie 请求；CORS 不是防刷或认证手段。托管服务监听可配置 HOST/PORT，不能保留仅 127.0.0.1 作为容器对外监听方式。
2. **数据构建与回滚**：移除 `/tmp` 依赖；固定来源版本、许可记录和校验和，在构建阶段生成两套索引。产物包括所有运行时模块及 OpenCC 依赖，构建期不上传用户草稿。不可变目录发布、校验后切换、保留上一版；新旧摘要与全文须绑定相同版本。
3. **游标与多实例**：现有签名密钥启动时随机生成，重启会让旧分页失效。首期可明确返回 409 并引导重新搜索；扩至多实例前须统一密钥与数据版本，不能让随机分流导致分页时好时坏。
4. **可用性**：增加 liveness/readiness；目录可读取不等于 worker 可搜索。配置自动恢复、优雅退出、错误率/排队/耗时/内存监测及告警。单实例仍有故障窗口，不能宣传高可用。服务失败时仍可继续当前创作、精选和自定义导入。
5. **成本与请求控制**：入口限流、请求长度/并发/超时限制、预算告警；服务端应尽量丢弃已断连的排队任务。前端 abort 当前主要防止旧结果覆盖，不能保证后端已取消计算。不在公开前端放任何托管平台密钥。
6. **容量验收**：先在本地做冷热查询、至少 30 分钟混合负载与内存观察，再在用户批准的目标实例上验证 1/3/5 RPS 及突发并发。以 p50/p95、错误率、worker 重启与 RSS 为准；目标如常用查询 p95 <1 秒须包含真实网络测试，尚未达成。
7. **回归与发布**：重复 231 项接口断言、编辑/选段/导出回归，补 iPhone 真机与目标地区网络测试。先小范围切换 API 配置，保留旧入口可回退；不自动删除旧静态数据。后续确认稳定再从 Pages 精简已迁出的数据，避免旧页面失效。

只读语料不需要一开始引入业务数据库。以后若换 SQLite/专用全文引擎，须先核对繁简归一、连续子串、多关键词、字段范围、相关度、缺文与原始版本；不能默认分词检索等价。

## 地区与使用体验

[Render 区域](https://render.com/docs/regions)包含新加坡，[DigitalOcean 区域](https://docs.digitalocean.com/platform/regional-availability/)也可选新加坡。暂以中文用户为主的试用假设评估这一地区；未验证大陆运营商到服务的延迟，也未验证服务默认域名可达性。后端加速不能解决 GitHub Pages 本身的页面或字体访问问题。

若以后决定中国大陆托管，需要将域名与备案流程纳入独立上线评估，不能因为只是 API 就默认免除；[阿里云备案说明](https://help.aliyun.com/en/icp-filing/basic-icp-service/user-guide/icp-filing-application-overview)明确讨论了大陆服务器与 API 域名的情形。本轮不选购国内套餐，不用首年促销价代表续费成本。
