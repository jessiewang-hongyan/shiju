# 代码架构

拾句是原生 JavaScript 静态网站。`dist/` 同时是可编辑源码和部署目录；无需打包，浏览器通过 ES modules 加载代码。开发工具仅用于格式化、静态检查和测试，不进入页面运行依赖。

## 模块职责

| 文件                        | 职责与主要接口                                                                   |
| --------------------------- | -------------------------------------------------------------------------------- |
| `dist/app.js`               | 初始化顺序、注入依赖、连接模块回调                                               |
| `modules/ui.js`             | DOM 查询、提示、对话框通用行为                                                   |
| `modules/poems.js`          | 首屏内置精选诗词，无需请求                                                       |
| `modules/storage.js`        | `createStore`；读取旧草稿与诗集、保存、历史快照                                  |
| `modules/editor.js`         | `createEditor`；唯一的集句编辑入口、选字、归还、撤销、调序、更换原文             |
| `modules/editor-paper.js`   | 编辑页拼贴覆盖层；复用毛边绘图，按原文字位和实际换行合并纸片，不拦截编辑操作     |
| `modules/collection.js`     | 诗集列表、保存、恢复、删除；恢复通过 editor 命令完成                             |
| `modules/library-loader.js` | 与 DOM 无关的加载服务；请求队列、分批校验、缓存、重试；可注入 fetch 和计时器测试 |
| `modules/library.js`        | 文集选择、全文搜索、预览、片段校验、自定义原文                                   |
| `modules/typography.js`     | OpenCC 加载及显示转换，原始字符与位置保持不变                                    |
| `modules/fonts.js`          | 字体配置与按作品用字加载分片；通过 getState 获取最新作品                         |
| `modules/image-drawing.js`  | 纯排版/绘图函数：换行、纸片合并、毛边、文字视觉居中                              |
| `modules/image.js`          | 当前作品两行预览、PNG 导出、图片字号和字体控件                                   |
| `modules/appearance.js`     | 夜览、页面字号、图片配色、拼贴与毛边选项                                         |

## 初始化与依赖

`app.js` 先创建 store 和 typography，再创建 editor、library、collection、fonts；随后创建 appearance 与 image，最后渲染。appearance 通过入口注入的回调请求重绘，不直接导入 image。image 从 appearance 读取配置。模块导入无循环依赖。

只有显式初始化函数绑定事件；单纯 import 不启动界面或网络请求。`ui.js` 的 DOM 查询在调用时执行。字体、文集、转换字典都按需请求。

## 数据结构与约束

```js
{
  source: { title, author, text, collection?, excerpt? },
  tokens: [{ c: '明', id: 12 }, { c: '\n', id: null }],
  title: '',
  signature: ''
}
```

- `id` 是 `Array.from(source.text)` 中的码位位置，不是字的内容或 UTF-16 下标。重复字是不同位置；标点和换行也占原文位置。
- 手动添加的标点、空格、换行使用 `id: null`，不挖空原文。
- 原文空缺由当前 tokens 的 id 集合推导，不单独保存一份，以免两边失步。
- editor 的 `mutate` 先存撤销快照，再更新、渲染和保存；最多保留 100 步。撤销历史仅存在当前页面。
- 原文替换会清空 tokens/title、保留署名，并允许撤销；诗集恢复保留作品数据，移除诗集条目的 id。
- 繁简转换只影响显示与导出，不更改底层原文和 id；转换结果必须保持码位数量一致。
- 其他模块通过 `editor.state` 读取当前状态，不缓存旧的 state 对象；修改作品使用 editor 命令。

## 图片绘制

预览和导出共用 `image-drawing.js`，保留各自的布局参数。预览是上下两区，每区最多两行；导出保留已有左右排版及完整内容。不要把预览的截断规则用于导出。

相邻纸片合并须同时满足：原文 id 连续、保持原顺序、在同一原文排版行；重新排序或跨行即拆开。字块内使用可见字形边界居中，不用字体基线猜测位置。毛边按原文 id 确定，重复绘制稳定。

## 存储与兼容

继续使用 `shiju-draft`、`shiju-collection` 及现有 `shiju-*` 设置键，不做数据迁移。草稿/诗集读写集中在 storage，外观偏好由对应控件模块管理。读取失败时保留默认值；写入失败通过界面提示，不假装保存成功。

文集与字体的 JavaScript 缓存只在当前页面存在，资源可以利用浏览器 HTTP 缓存。这里尚无离线存储或跨设备同步。

## 修改约定

- 新编辑动作走 editor 的变更通道，不直接在文集/图片模块修改状态。
- 新图片效果优先写入共享绘图函数，并验证预览与正式导出。
- 数据请求逻辑与 DOM 分离；错误处理需保留已完成部分。
- 不修改存储键和格式，除非同时提供迁移方案与测试。
- 修改后执行 `npm run check`、`npm test`，再按验收清单检查真实浏览器。

### 字号联动

页面原文字号和图片字号共用 5–25 范围。`appearance.setSourceSize` 在用户操作时通过 `onSourceSizeChange` 通知图片模块；`image.setImageSize` 更新预览、图片控件，并无回调地同步页面控件，避免递归。两份旧存储键同步保存，启动时优先使用原文字号、其次图片字号。导出原文与集句正文均按该值相对 23 的比例缩放。

### 图片布局

`image-layout` 支持 source-left/source-right/source-top/source-bottom，默认原左新右，保存至 `shiju-image-layout`。预览按布局排列两个最多两行的模块；导出先按模块宽度换行、测量标题，再计算模块高度与位置。上下布局使用全宽，署名始终属于集句模块。长文超过 24000 像素时沿用长度保护。

编辑页纸片通过 `data-source-id` 对应原文字位；监听编辑重绘、尺寸、主题变化，图片设置通过 `onPaperChange` 通知刷新。只同步拼贴、毛边与强度，颜色沿用页面日间／夜览主题；每段纸片使用独立小画布，避免长文生成超大覆盖层。

手工拼贴通过 `handmadePlacement` 按纸片首字位置生成稳定的旋转和上下偏移，长纸片限制边角抬升高度。预览与导出共用 `paintCollageLine`，编辑页文字与纸片使用同一变换中心；关闭开关恢复正常位置。

手工拼贴两个强度值为 0–100 的最大幅度系数（默认 50），各纸片按固定种子在正负区间近似均匀取样；倾斜上限 0.15 弧度并受长纸片高度约束，上下位移上限为纸片高度的 24%。两个值独立保存和应用，0 对应零变换；手工模式增加行距以容纳偏移。

### 纸张背景与裁剪

`paper-materials.js` 负责按需加载、本地缓存和共享纸面绘制。`source-paper`、`poem-paper` 独立保存至 `shiju-paper-source`、`shiju-paper-poem`，旧用户默认纯色。加载失败保留前一选择并允许重试；PNG 导出等待素材就绪。

纸面是虚拟场，不随长文生成一整张超长纹理。基础纹理使用 840 像素小画布；纤维纸和素纸区域通过镜像拼合保持边缘连续；洒金的不规则碎片跨边界重复绘制。十竹斋单独的装饰只绘制在底部一次，并对衔接区域羽化。照片纹理仍可能有可辨认的重复结构，不宣称无限非重复。

编辑页使用同一纹理的 CSS 背景；预览与导出使用 `paintPaperField`。字块通过 `paintPaperCrop` 从原文布局中取对应坐标，再以共享毛边遮罩裁切；原处覆盖同形空洞。响应式编辑页、两行预览和导出有各自排版宽度，图案随该处原文排版取样，不保证不同布局下同一字符背后是逐像素相同的图案。选用纹理时正文采用图片配色以保证夜览中的文字可读，其余页面仍沿用夜览主题。

素材与许可随 `dist/assets/papers/` 部署。完整来源见 `paper-materials.md`。

## 横竖屏导出与纸片间距

图片方向由 `image-orientation` 决定并持久保存。横屏 4:3，起始 1440×1080；竖屏 3:4，起始 1080×1440。切换方向会将左右布局映射为上下布局，单模块选择保持不变。`image.js` 根据方向重新排版并检查内容所需高度；长文扩大画布、保持比例并重新换行，不缩小字形。超过 24,000 像素单边或 64MP 时提示拆分文章。

`wrapCells` 优先整块换行，只有大于一整行的字块才按字拆行；`gapBefore` 仅加在独立字块前。同块内按固定 advance 绘制，不因拼贴间隔而变化。原文发生排版变化后，仍按字符 ID 的当前位置取纸纹，不冻结历史纹理。

模块留白由 `image.js` 中的 panelPadding/panelGap 控制，存储在 shiju-image-padding/shiju-image-panel-gap。预览按半尺度展示留白，导出按画布像素应用。内边距参与文字宽度、标题/正文位置、纸张采样坐标和模块高度计算；两个模块作为整体在正文可用区域纵向居中，不拉伸模块背景来消耗固定画幅的剩余空间。

### 标题、作者选字

`source-parts.js` 统一划分标题、作者、正文的字符位置。正文保留旧的 0 起始 ID；标题从正文长度 + 1 开始，作者从正文长度 + 标题长度 + 2 开始，段间保留一个 ID，避免跨段拼接。旧草稿无需迁移。编辑页用 `source-sheet` 作为包含元信息的完整纸张背景，导出登记标题、作者的换行和裁剪坐标；不同字号的元信息纸片按原位置裁出，保留来源字号与纸片宽高。预览在元信息有选字时优先显示其空缺，仍最多两行。

`sourceMetrics` 为画布布局提供每字的来源字号、步长及宽度单位，换行与拼贴绘制共享这些度量。编辑页从来源字格读取实际字号和宽高；预览使用同一来源比例。原文正文的字号调整不会将标题或作者纸片统一缩放为正文尺寸。
