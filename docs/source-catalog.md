表中“问号”指只命中 ASCII `?` 的记录；“缺字符号”指含 `�`、`□`、`〓` 的记录，仍须人工核对。空作者不等同于作者佚名。

### 已发现的接入问题

- **古文观止**：解析为 222 篇，保留 12 卷及原篇题。19 篇只命中 ASCII 问号；抽检为问句标点，不应自动隔离。仍需正式接入时核对来源、标点及版本。
- **经典计数**：《大学》《中庸》各 1 个整篇单元，《孟子》14 篇，《论语》20 篇；不是 36 首诗。`四书五经` 目录只提供大学、中庸、孟子，不能标称覆盖四书五经全本。
- **缺作者不等于正文缺损**：《幽梦影》219 则、《曹操诗集》26 条及部分经典无逐条作者字段。专集归属可以保留，但不能在审计阶段猜补每条作者。
- **文字蒙求**：4 卷，作者字段包含传记，不能原样进入可摘取的作者行；卷三含 `□`。最长卷超过 25,000 字，应按章节/连续段落选择，不默认整卷导出。
- **三字经**：传统版与新版分开；新版含清末后的编写内容线索，编写版本和使用依据需另查，不统一按古代原本处理。
- **千家诗**：有组诗嵌套子题；本次以叶级正文解析为 226 个单元，不以书名或外部常见篇数替代实测。
- **选本数量与名称不同**：唐诗三百首有两份版本，分别解析为 366、320 个单元；宋词三百首为 280 条。保留版本名与原有组织，不强行凑为 300 条，也不宣称完整本。
- **宋词**：现有导入脚本只取编号分片；上游另有 `ci.song.2019y.json` 的 3 条补录。本轮源库共 21,053 条；这 3 条未与现库正文匹配，是否补入须先核对版本和混合简繁，不能仅以已接入“宋词”认定源文件已覆盖。
- **御定全唐詩**：900 个卷文件；`biography` 与 `notes` 不进入正文，`volume` 留在出处层级。它与其他唐诗版本需要关联，不重复堆叠为独立新作品。
- **纳兰性德**：部分正文包含括号署名的联句，不能盲目删除括号；需确认导入的作者展示及正文边界。

- **空正文**：共 170 条（元曲 143、唐诗 4、宋诗 23），保留审计定位，但不作为可创作原文。它们与“有文字、仅部分缺失”的残篇不同。

### 推荐接入批次

1. **新文体试点**：古文观止、幽梦影、声律启蒙、论语、大学、中庸、孟子；先解决缺省作者、篇章显示、选段及正文边界。
2. **补齐古代时间段**：先秦、秦、辽及各跨朝代分类；与之前已审计的南北朝至清数据一起按需分片。
3. **专集与选本**：曹操、纳兰性德、千家诗和各三百首等，先关联重复来源，再提供专集入口。
4. **大规模版本补全**：chinese-poetry 的唐诗、宋诗、御定全唐詩，结合 Werneror 朝代库制定搜索去重与版本展示；不默认两个来源互为补集。
5. **暂缓项**：六个近现代相关分类与三字经新版；只有结构及质量审计记录，没有确认公开提供原文服务的依据。

验收：原九类的记录数、命中标记数、现库重合数及内部重复计数与前轮报告一致；所有文件解析数与分组合计一致。8 项新脚本测试及原 4 项审计测试通过。未修改 `dist/`，不需要将此次文档检查表述为页面功能验收。


## 正文边界与接入规则

1. 只解析显式正文键 `paragraphs`、`para`、字符串形式的 `content` 及嵌套章节中的正文；保留卷、章、篇、组诗小题和源文件定位。
2. 不把 `abstract`、`comment`、`notes`、`prologue`、`spells`、`origin`、作者传记、排名或格律数据当成集句原文。序言本轮不自动纳入；即使属于古文，也需作为独立篇目另行核对。
3. 书目作者、编者和篇目作者分开。选本不能把编者继承为所有篇目的作者；缺作者先保留为空，不自动推定。目录能提供作者线索的专集可以在接入阶段建立有出处的补充映射。
4. 没有原题的语录按原有次序提供“第 N 则”等导航名称，不能伪造为原题；标题缺失与正文损坏分开统计。
5. 经典和古文按源章节作为可选单元，允许连续选段；不能将整书与独立一首诗的数量相加后宣称“共多少首”。
6. 作品名含“赋”不等于已可靠识别文体。保留上游书名和章节；诗、词、曲、赋、散文的筛选标签需有依据，否则标为未标注。
7. 不直接拼接多个版本。唐诗、宋诗、选本、作者专集与 Werneror 朝代库之间采用“作品—来源记录”的关联，版本、异题与异署名保留。
8. 有正文的残篇允许接入，原有缺文标记原样保留，不因命中标记而默认排除、不猜补、不删除。缺文性质需区分原缺、转录/编码疑点及未判定；`?` 可能是问号，`�` 不能直接认定为古籍原缺。作者字段污染、空正文、异署名继续单独复核。括号也不自动删除。
9. 纳入全部古代文集的目标采用分批数据接入与按需分片加载；跨库搜索索引、长段落选取、失败续载和导出另做产品验收。

## 残缺文献与缺文拼贴（用户确认的接入规则）

- **保留原缺**：允许有正文的残篇进入文集，展示“含缺文”或“含待核对标记”等准确说明；疑似转录错误不标称已确认的古籍残缺。
- **可裁剪**：原有 `□` 等缺文标记作为有独立来源位置的可选单元，支持摘取、相邻合并、重新排序、归还及重复字符定位。保留标记本来的字面形式，不把 `□□□` 压缩为一个符号。
- **区分两类空**：原文自带的缺文，与用户摘字后形成的洞，必须有不同状态。前者可摘取；后者点击时归还已摘取单元。不能因为二者视觉上都像空白而混用。
- **不制造缺字数**：普通排版空白不能自动当作缺文；“阙文”“阙若干字”等说明不能擅自扩展为若干方块。长度不明的缺文保留原表示。
- **图片一致**：缺文单元与普通字块遵循相同的来源位置、纸纹、毛边、字号、合并与拼贴规则，编辑预览和导出保留同一标记；所选字体没有该符号时需要回退显示，不能静默消失。
- **空正文不接入**：只有题名、作者而没有任何正文的记录保留在审计中，不能作为默认可选原文。

以上是后续数据接入与功能验收要求，**本轮未修改编辑器实现，也未声称已完成缺文裁剪的交互验收**。后续应覆盖连续缺文、重复缺文符号、缺文和普通字混合合并、归还、简繁切换、字体切换、草稿恢复及 PNG 导出。

## 审计口径与复现

- 正文比较：NFC，去空白及 Unicode 标点，SHA-256；不合并简繁、异体字，不做相似度或片段包含匹配。
- 完全重复：标题、作者、未经规范化正文完全相同。正文重复不代表可以删除；同正文异作者或异标题需校勘。
- 缺字标记：`?`、`�`、`□`、`〓`；问号也可能是合法标点。空标题、空作者、空正文单独统计。
- 作者字符串超过 40 字列为字段复核候选；正文中的括号和超过 10,000 字的单元单列检查，不自动视为错误。
- 与现库的对照范围为 `dist/data/*.json` 中完整文集，排除八篇内置精选。报告保存现库文件 SHA-256。
- 来源与文件覆盖：[文件总清单](source-catalog-inventory.json)；统计：[内容审计摘要](source-catalog-audit.json)；定位、重复与质量候选：[完整明细（gzip JSON）](source-catalog-details.json.gz)。完整明细不复制正文。

复现时从上述固定 commit 获取递归树（GitHub `git/trees/{commit}?recursive=1`），分别保存为 `SNAPSHOT/tree.json` 与 `SNAPSHOT/werner-tree.json`，确认 `truncated=false`。按文件总清单下载所有 `group` 非空的正文文件，保存为 `SNAPSHOT/{repo 第一段}/{path}`；将这些记录的 `repo`、`commit`、`path`、`bytes`、`sha256`、`git_blob` 写成 `SNAPSHOT/catalog-sources.json`。不需要下载被排除的辅助资料。脚本逐个验证长度、SHA-256 和 Git blob SHA-1，再解析；未知结构报错，不静默略过。
