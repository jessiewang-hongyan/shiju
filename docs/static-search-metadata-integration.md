# 仅篇名与作者静态搜索：本地接入验收

日期：2026-10-29。状态：本地已接入，未提交发布或推送。线上保持原样。

## 范围与实现

本地编辑页：http://127.0.0.1:4181/editor/ 。使用现有“更换原文”弹窗，保留默认“篇名与作者”、仅篇名、仅作者及文集筛选，移除全文选项、全文提示；独立搜索服务端口 4180 保留作为对照。全文索引仍保留在实验磁盘，用于旧版对照，新静态搜索不使用它们。

19 个外部文集共 443,692 篇（包含评估用宋库），精选另有现有入口。用户确认作品前不修改创作。原始正文、缺文、标题作者保持源数据；关键词繁简归一化只用于检索。

新目录保存每个字的候选数量和分片文件。查询选择最稀少的字读取一个候选分片，按文集和字段验证完整关键词，然后按篇名相关度排序。候选已带规范化标题作者，省去旧版多文集索引清单、倒排位置块和排序块请求。首屏摘要最多四路并发、同块合并；点击后才取原始正文块（每块最多 128 篇，并非单篇下载）。空查询仅读目录及首屏摘要。

编辑器通过可注入请求函数复用现有原文弹窗适配层；本地静态服务器只注入配置和模块入口，不执行查询。Worker 延迟到文集使用时启动，OpenCC 延迟到首次非空关键词加载。正式 dist 的 app 入口不包含实验路径依赖。

## 性能对照

以下为本机受控 Node 客户端对照，gzip level 6 的数据负载，不含 JS、OpenCC、HTTP 头或公网往返。每场景独立进程冷缓存，服务端对照已运行并可能有缓存。详细耗时、内存及重复查询见 `prototype/static-search/benchmark-metadata.json`。

| 全库·赤壁赋       |    1,020 KiB |    316 KiB |      110 → 20 |
| 宋·作者苏轼       |      709 KiB |    354 KiB |       89 → 17 |

| 全库·篇名作者明月 |    1,304 KiB |    649 KiB |      257 → 47 |
| 全库·空查询       |      703 KiB |    136 KiB |        40 → 3 |

赤壁赋的数据量下降约 69%，请求数下降约 82%；各查询改善幅度不同。独立服务同场景通常仅一条摘要查询、约 2–5 KiB，仍更省客户端流量。

关键词首次查询还需要 OpenCC 脚本约 500 KB gzip，不应把表格数字当成整页首次下载量。延迟加载省的是未搜索时的加载，不会消除第一次查询的转换库成本。内存记录为 Node 搜索逻辑代理，不是 iPhone 或浏览器总内存实测；8 MB 缓存限额也不是总堆上限。

## 代价与后续上线条件

新候选分片共 6,752 个，原始 JSON 合计 326,849,759 字节（约 312 MiB），因为标题作者会随所含字符重复保存，明显大于旧的纯元数据索引。这是以静态存储换取更少网络往返。另需摘要约 74.85 MB、正文约 225.24 MB 及清单；浏览器不会整库下载。

因此本次没有判定可直接上线：仍需检查静态托管配额、完整产物体积、压缩缓存策略及移动端弱网表现。数据目前在 `/tmp/shiju-static-search`，不是永久发布产物；被系统清理后须按 README 重建。旧实验文件用于对照，上线产物应仅包含实际所需版本。

Worker 串行处理查询，过期请求不会更新界面，但已开始的计算不会立刻取消。需要更严格的手机压力测试后再决定是否改取消调度。
