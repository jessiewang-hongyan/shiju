# 静态搜索与独立服务对照

> 更新：仅篇名与作者的第二轮优化已接入本地原文弹窗。最新数据、验收与存储代价见 [本地接入验收](static-search-metadata-integration.md)。下文保留第一轮对照，不代表当前本地版本。

日期：2026-10-29。原型 http://127.0.0.1:4181/ ；独立服务编辑页 http://127.0.0.1:4180/editor/ 。未上线，现有四种范围保留。

## 结论

独立摘要有效降低首屏数据和部分内存开销，但不能消除静态搜索的索引传输。若坚持零后端费用，并愿意仅支持篇名与作者，改进静态值得继续；若要维持全库全文搜索和较低手机传输量，当前独立服务仍更有优势。不能根据本地 50 ms 与 HTTP 80 ms 的差异判断公网静态更快。

仅保留篇名、作者检索会把两套归一化搜索索引从 192.58 MB 减到 22.36 MB，移除全文索引约 170.22 MB，即减少 88.4%。这是搜索索引磁盘体积，不是整个网站或所有首搜流量缩小 88%。原文、摘要、排序表、字体仍需要保留。

当前默认“篇名与作者”已经只加载 metadata 小索引。因此，关掉全文不会进一步减少这一默认查询的索引请求；本次默认搜索改善主要来自摘要分离。用户若只记得诗句正文，将无法用该诗句找作品，这是功能取舍。

### 首次打开不能漏算程序本身

上表只含搜索数据，不含脚本页面。静态原型页面、Worker、搜索模块、OpenCC 等启动文件合计约 **493.0 KiB gzip**，主要是繁简转换库。首次打开再搜宋库“明月”，约为该启动量加表中的搜索数据，即约 **1.41 MB**。HTTP 头部、TLS、原始全文点击、编辑页样式和字体不在此统计中。接入编辑页时若 OpenCC 已加载可能复用，但尚未验证跨 Worker 的加载与内存复用，不能预扣。

实际桌面浏览器首轮原型搜索赤壁赋约 283 ms、109 资源，后续新建 Worker 搜宋库作者歐陽修约 137 ms、23 资源。这里只用于确认浏览器路径真实运行，不能替代公网首搜测量。很多小文件在高 RTT 下有额外延迟，本机结果看不到；后续应减少 manifest/排序块请求并做真实弱网验收。

## 产物与代价

新增摘要约 74.85 MB、排序块约 18.76 MB、全文块约 225.24 MB，均未压缩。使用小索引时上述数据加索引约 341 MB，使用两套索引约 511 MB，另加代码、清单、字体等；未组装完整上线包。摘要新增存储换取列表少读正文；不能将它描述为存储零代价。临时目录有多版产物，磁盘 du 会高于单版大小，未清理历史版。

全文按 128 篇一块；点击一篇仍会读取所在块，并不是逐篇文件。空查询及高频单字命中很多，相关度排序可能需要大量标题块；例如宋库“春”仅篇名作者的静态首搜仍约 3.83 MiB 搜索数据。不能保证任何查询都低于 1 MB。

## 验收与边界

- 11 场景 × 3 路线总数和首屏顺序一致，重复查询一致，抽样打开全文与原数据逐字段一致。
- 额外 32 条断言：繁简混合、文集与字段组合、第二页、缺文、正文和版本、摘要阶段无正文、小索引模式无全文索引。
- 浏览器验证实际静态 Worker 搜索、作品预览、分页、仅篇名作者试验开关。
- 本轮没有修改 dist 编辑器、用户草稿或线上发布；原型根页只搜索与预览，不复制编辑/导出功能。
- 没有做 iPhone 真机内存、远程弱网、长期并发/服务端内存压力测试。若要据此替换线上，以上仍是验收条件。

## 建议的下一步

先确认是否正式取消全文搜索。若确定以零后端费用为优先，下一轮集中优化仅篇名作者：缩小全库 manifest 首载、将必要排序信息融入小索引、减少分散摘要请求，并处理转换库启动体积。保留繁简、相关度与来源版本，随后将静态适配器接入本地原文弹窗再做手机验收。当前不移除原服务，便于继续对照或回退。
