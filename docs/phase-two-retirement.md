旧壳是为缓存 HTML 仍可打开编辑器而保留的过渡项；它本身并不能提供旧索引。**如果产品要求最早标签页不刷新也能持续检索，则不应直接移出这 460 MB**。本地按“当前一期可继续搜索、更早一期允许刷新”的口径验收。旧标签页何时自然退出没有线上观测数据；未对公网 CDN 缓存及远程正文供应重新验收。

[仅回退包文件逐条清单](evidence/phase-two-retirement/rollback-only.txt)；[主站保留的一期基线文件](evidence/phase-two-retirement/main-retained.txt)（另含二期候选自身的入口、清单、样式和模块）。[文件数、站点／归档大小与 SHA-256](evidence/phase-two-retirement/sizes.json)。独立回退归档内的每一个文件均按实际部署过的一期清单核对；含一期入口及两代全量搜索资源，不依赖精简包补文件。两份静态包的远程正文仍按各自原有设计加载。

[实际浏览器结果](evidence/phase-two-retirement/browser.json)：同一隔离本地地址先打开较早一期，再切到精简包；未缓存的旧检索失败，手动刷新保留草稿并迁移。当前线上一期的常驻页面切包后仍可检索《关雎》，出现“保存并更新”，不会主动刷新；点击后新版保留当前二期创作并识别旧页修改。实际换回独立一期归档，旧草稿及检索恢复；再升级，二期草稿仍在。移出配置在两包分别实测为 404 和 200。

复现：scripts/audit-retirement.py 从经校验的完整候选与生产清单生成两个本地归档（拒绝覆盖已有归档）；prototype/multi-source/upgrade-server.py 接受候选与回退两个归档。在新端口打开 /retirement-lab.html 运行。不修改正式构建的 retain-current 策略。

用户已接受更早一期标签页需要刷新。精简候选后续完成 22 个文集逐库抽样、混合摘字、完整备份恢复及两种 PNG 输出回归，详见 [精简候选验收](phase-two-slim-acceptance.md)。仍仅本地，未上线。
