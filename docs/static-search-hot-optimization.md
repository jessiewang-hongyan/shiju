# 高命中单字与搜索转换库优化

2026-10-29；已接入本地 4181 编辑页，未部署、未推送。

## 本次实现

- 对规范化后候选达到 10,000 条的 82 个单字，构建按篇名相关度排好序的 ID 分页。分别保留三种字段和各文集范围的准确总数与分页，不截断结果。每块最多 256 个位置 ID；首屏只读覆盖当前 40 个结果的块，然后读取对应摘要。
- 其余查询仍走原候选分片。多字或多词查询即使包含高频字，也会选择候选最少的字后过滤；此次没有改成多词预计算。因此不能承诺所有宽泛多词查询都不会超时。
- “其”的原始候选分片约 1,773 KB gzip；现在先读约 28.7 KB 的分页清单和约 0.6 KB 的第一页 ID。结果摘要另外按需读取，不能将 29 KB 宣称为完整首查下载量。
- 搜索 Worker 首次非空查询只导入 `search-converter.mjs`，来自现有 OpenCC 的 t→cn 完整词典链和 Trie 算法，包含兼容字归一化；不删除词条、不改检索字形规则。生成器检查是否新增了分词配置，避免静默使用不支持的转换链。
- 原编辑器繁简转换功能仍保留完整 OpenCC，因为它还需要简转繁。搜索精简包不会替换编辑器的双向转换功能，也不能替代全站完整包的发布文件。
- 精简搜索转换包：48,066 字节原始 / 29,477 字节 gzip；原完整包：1,195,473 / 512,716 字节。搜索首次转换库下载减少约 94%。原许可证和第三方许可仍在 dist/vendor/opencc，生成文件有来源标注。

## 相同弱网参数复测

真实引擎加定时共享带宽模拟，桌面 CPU，先打开文集、再首次输入关键词；下面包含转换库下载，不包含编辑页启动及打开文集的约 1.3/2.5/4.8 秒。不是 iPhone 真机结果，也不包含真实丢包或手机 CPU 降速。

| 网络参数            |   赤壁赋旧→新 | 宋·作者苏轼旧→新 |    宋·春旧→新 | 全库·其新 |
| ------------------- | ------------: | ---------------: | ------------: | --------: |
| 1,600 kbps / 150 ms |   5.3 → 2.8 s |      5.3 → 2.8 s |   7.5 → 3.7 s |     3.4 s |
| 800 kbps / 300 ms   |  10.5 → 5.5 s |     10.4 → 5.3 s |  14.7 → 7.2 s |     6.5 s |
| 400 kbps / 600 ms   | 20.9 → 10.8 s |    20.6 → 10.6 s | 29.3 → 14.2 s |    12.9 s |

“其”旧版在同参数浏览器中触发 35 秒超时；新版同为 390×844 视口、400 kbps/600 ms 下返回 **144,468 篇**，首条为《其源》，显示更多从 40 增至 80，截图 `/tmp/shiju-mobile-hot-optimized.png`。13 秒是定时引擎模拟结果，浏览器目视验收用于确认返回和布局，不能当成精确浏览器秒表结果。

重复同查询命中缓存；分页和打开原文在模拟中均成功。完整记录：`prototype/static-search/benchmark-weak-before.json`、`benchmark-weak-optimized.json`。基准脚本继续可复现，旧结果已保留，不覆盖旧基线。

## 正确性与检查

- 897,375 项转换对照：全部外部文集原始标题/作者、原 t→cn 链每个词条及上下文、繁简混合、兼容字符、补充平面字符、空输入，均与完整 OpenCC 一致。
- 174 条搜索断言：其、春、一、二、其 春、赤壁賦；篇名作者/仅篇名/仅作者；全部文集与宋；首屏、下一屏、跨 256 边界的 offset 250。总数、内容、顺序和下一页均与上轮静态引擎一致。高命中单字断言不请求大候选分片。
- `npm run check`、`npm test` 64 项通过。
- 验证脚本：`verify-converter.mjs`、`verify-hot.mjs`；结果 JSON 同目录。

## 存储代价与上线状态

新增单字分页文件约 **53.35 MB**（gzip 合计约 11.93 MB），共享内容哈希文件会去重。保守发布清单由约 843.83 MB 增至 **897.23 MB**；排除之前确认运行时不用的完整字体副本后约 **755.15 MB**。本次未删除任何字体文件或旧数据。

单字分页提高首查速度，但增加约两万个小文件。上线前仍建议做明确的产物清单、子路径打包验收，并进一步合并小文件或按文集拆分大候选。旧整套数据和历史版本不可随新包叠加发布。当前最快方案仍只在本地，真机和公网表现尚未验收。
