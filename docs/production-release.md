## 发布方式

- 页面保留 GitHub Pages 地址 `https://jessiewang-hongyan.github.io/shiju/`。
- 数据仓库：`jessiewang-hongyan/shiju-data`，具体提交由 `release-data.json` 固定。
- 索引、摘要随 Pages 发布；打开作品时才从固定提交的 raw.githubusercontent.com 地址下载正文块。无需独立搜索服务器，不接入收费服务。
- 页面搜索范围为篇名与作者、仅篇名、仅作者；取消全文搜索。
- 保留原有编辑、草稿、诗集、选段和图片设置。
- 构建入口 `scripts/build-release.mjs`，部署目录 `_site/`。入口脚本、样式、模块目录、配置使用版本化文件名；正文同时校验版本及 SHA-256。

## 性能口径和限制

`scripts/benchmark-release.mjs` 用最终构建引擎及固定数据，对 1600 kbps / 150 ms、400 kbps / 600 ms 共享带宽模拟各做三轮。分开记录文集初始浏览、首次查询（含精简转换库）、重复查询、打开正文。不是 iPhone/Android 真机测量，不包含页面启动、TLS、丢包、无线调度或手机 CPU；不能据此承诺所有网络下的响应时间。

已做桌面浏览器及窄屏/弱网模拟。真实手机 Safari/Chrome、系统软键盘、Wi-Fi/蜂窝切换和实际存储配额仍未实测，保留为发布后跟进项，不标成通过。GitHub Raw 在不同地区的可达性仍依赖用户网络；失败有超时、重试及自定义原文入口。

## 发布顺序与回滚

1. 先推送固定版本的数据仓库并验证公网正文及 CORS/SHA。
2. 提交主仓库代码、构建入口和固定数据引用，推送 main。
3. Actions 执行检查、测试、构建、全量资源及正文映射校验，然后发布 Pages。
4. 核对公网 `release.json`，验证搜索、正文、选段与编辑导出。

回滚基线：主仓库提交 `e231436`。若核心流程故障，优先 revert 本次发布提交，恢复原有 dist 部署流程后重跑 Pages；不删除数据仓库固定提交，避免已打开页面丢失正文。版本化新模块避免旧浏览器缓存误读新代码；用户草稿保留原有存储格式。首次迁移保留旧版 app.js、style.css、modules/、data/，供已打开或缓存旧 HTML 的页面继续访问；新入口不加载这些兼容数据。后续独立评估移除窗口，不在本次提前删除。
