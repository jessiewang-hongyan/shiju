## 本轮交付

1. 发布版增加版本变化提示。读取 `release.json`，在页面初次加载、返回前台、搜索返回错误或前台每 60 秒检查。网络失败、离线和无效版本号不误报更新。
2. 用户主动点击“保存并更新”才刷新。草稿先写入并回读核验；集合可读性检查通过才继续。存储抛错、静默丢弃写入或集合损坏均阻止刷新，并提示先导出图片或备份作品。不会自动清空创作或强制更新。
3. 检查不会用本标签页的过期诗集副本覆盖存储中的新诗集。未改变原有 `shiju-draft` / `shiju-collection` 存储结构，自定义原文、缺文标记、标题、署名和摘字 ID 保留。
4. 构建器可显式保留指定旧发布包的版本化脚本、样式、模块和静态搜索数据，逐 URL 检查冲突；相同 URL 的不同内容会终止构建。当前发现用的可变 `static-data/current.json` 不覆盖，新旧引擎各自引用固定哈希配置。
5. `RELEASE_LEGACY_MODE=retire-preview` 仅允许本地预览，并在正式构建写文件前拦截。默认继续保留最旧兼容层；没有把未经确认的淘汰策略变成默认正式发布行为。

## 清理范围与边界

### 最旧兼容层（e231436 一代）

- `app.js`、`style.css`、`modules/`、`data/` 共约 293 MB。
- 本地迁移预览已排除这些路径，新版和当前线上固定版本均不依赖它们。
- 更早缓存 HTML、已打开且已经执行旧 JS 的标签页仍可能依赖它们。新构建无法给已经执行的旧 JS 补上更新检查，也不能让旧的 URL 自动改指向其他仓库。
- 因此，能够列为“退出该代支持后可清理”，不能列为“对所有历史常驻页面无影响”。本轮没有从正式站或源码资料中删除它们。
- 数据来源和字体许可仍保存在候选 `licenses/`、`vendor/`、`fonts/` 内，不能随兼容数据统一删除。

### 当前线上固定版本

- `app-15a52e2940ed593e.js`、对应样式、`modules-15a52e2940ed593e/`、固定哈希配置及其索引／摘要目录，本轮完整保留。
- 原正文继续由旧版本原有固定 Git 提交提供；发布新正文时也不能删除该提交。
- 此版本本身没有新增更新提示；保留其资源让其继续运行。只有加载本轮或后续代码的页面才能显示新提示。
- 等该版本也按明确支持策略退出后，才可移除这些固定路径。仅等待几天不能证明所有常驻标签页都已刷新。

### 必须长期保留的恢复基础

- 当前版本用到的脚本、索引、字体、纸张、许可和正文固定版本。
- 可恢复的历史发布包及数据提交（可以归档，不能将 Git 历史存在误认为 Pages 仍托管原路径）。
- localStorage 草稿与诗集；不得把清缓存或清空浏览器数据作为更新步骤。
